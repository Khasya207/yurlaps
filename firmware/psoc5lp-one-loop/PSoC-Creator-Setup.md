# PSoC Creator 4.4: build, flash, test and recover

These instructions are written for a Windows user who has not used PSoC Creator
before. Menu/button names are kept in English as shown by the program.

> **Use a spare CY8CKIT-059 for the first test if possible.** Programming erases
> the firmware currently in that PSoC. Your original decoder can be restored
> from the published HEX, but a spare board keeps the working race decoder safe.

## 1. Install the Windows tools

1. Download and install **PSoC Creator 4.4** from Infineon. PSoC Creator is a
   legacy Windows-only tool, distinct from ModusToolbox.
2. Include these installer features:
   - PSoC Creator;
   - PSoC 3/4/5 device support;
   - PSoC Programmer;
   - KitProg and USB-UART drivers.
3. Reboot Windows after driver installation.
4. Plug the wide PCB USB/KitProg end of the CY8CKIT-059 into a USB port. Do not
   use the target-side micro-USB connector for programming.
5. In **Device Manager**, confirm that a KitProg device and **KitProg USB-UART
   (COMxx)** appear.
6. Open **PSoC Programmer** once. If it offers a KitProg firmware update, apply
   it, unplug the kit and reconnect it.

Official board page and manuals:

- <https://www.infineon.com/evaluation-board/CY8CKIT-059>

If the kit is unknown in Device Manager, manually select the KitProg driver,
typically under:

```text
C:\Program Files (x86)\Cypress\Programmer\drivers\KitProg\KitProg.inf
```

## 2. Preserve the working decoder

Before touching the in-service board:

1. Save a local copy of the known-good published RCHourglass decoder HEX.
2. Write down which version currently works.
3. Photograph all P12[2], P12[3], P12[6], P12[7], 5 V and GND connections.
4. Disconnect the loop amplifier/coax and any external 5 V source while
   programming. Avoid powering the target from USB and an external supply at
   the same time unless their power arrangement is known to be safe.

The original compiled image can be programmed again later with PSoC Programmer.
Reading the original back from the chip is not a substitute; protection settings
may prevent a useful readback.

## 3. Create the Creator project shell

PSoC Creator's schematic (`.cysch`) is a proprietary binary generated by the
Windows tool, so create this small shell locally:

1. Start **PSoC Creator 4.4**.
2. Select **File > New > Project**.
3. Select **Target device** and choose exactly:
   `CY8C5888LTI-LP097`.
   - If the kit templates are installed, selecting `CY8CKIT-059` is equivalent,
     but still verify the exact device.
4. Select **Empty schematic**.
5. Use workspace name `OneLoopDecoderWorkspace` and project name
   `OneLoopDecoder`.
6. Put it in a simple local path, for example:
   `C:\YurLaps\OneLoopDecoderWorkspace`.
7. Click **Finish**.
8. Open **Project > Build Settings** and select the bundled **ARM GCC**
   toolchain. The capture buffer uses GCC alignment so one DMA extended-address
   word can safely address the entire 4096-byte ring.

PSoC Creator creates:

```text
OneLoopDecoderWorkspace\
  OneLoopDecoderWorkspace.cywrk
  OneLoopDecoder.cydsn\
    OneLoopDecoder.cyprj
    OneLoopDecoder.cydwr
    TopDesign\TopDesign.cysch
```

## 4. Add the firmware source

Copy every `.c` and `.h` file from this repository's
`OneLoopDecoder.cydsn` source directory into the newly generated
`OneLoopDecoder.cydsn` directory. Do not copy `host-tests`.

In Creator:

1. Right-click the `OneLoopDecoder` project in **Workspace Explorer**.
2. Select **Add > Existing Item...**.
3. Select these C files:
   - `main.c` (replace/remove Creator's empty template if necessary);
   - `capture_dma.c`;
   - `passage_tracker.c`;
   - `rch_demod.c`;
   - `rch_protocol.c`;
   - `serial_console.c`;
   - `timebase.c`.
4. Repeat for all corresponding `.h` files.
5. Never edit files under `Generated_Source`; Creator regenerates them.

## 5. Build TopDesign exactly

### Why there is no Comparator component in stage one

When this project is installed on the published/original decoder PCB, the coax
is **not** connected directly to the PSoC. Q1-Q4, C1/C2 and the R9/R10 bias node
already amplify/limit and condition the 5 MHz signal before it reaches P12[2].
The P12[2] digital input buffer is the decision threshold, while P12[3] feeds the
same logic level back through R11 = 4.87 kOhm to add external hysteresis.
Therefore a PSoC Comparator component would duplicate the existing decision
stage and is not part of this original-PCB-compatible TopDesign.

If Q1-Q4 are removed, or a passive/new analog receiver is connected instead,
then a sufficiently fast **external comparator or limiting receiver must be
placed before P12[2]**. Never connect raw loop/coax or an analog sine signal
directly to P12[2]. Keep the PSoC side as a digital input after that external
comparator. The future universal receiver design is a different front end and
will include comparator/limiter and RSSI circuitry.

Open `TopDesign.cysch`. Add the following components from **Component Catalog**.
Component instance names are case-sensitive because the C source uses their
generated APIs.

### Required components

| Catalog component | Instance name | Essential setting |
|---|---|---|
| Digital Input Pin | `LoopIn` | HW connection, digital high-Z, transparent/unsynchronised input, rising-edge interrupt |
| Digital Output Pin | `HystOut` | HW connection, strong drive, fast slew |
| Interrupt | `LoopEdgeISR` | Derived interrupt |
| Clock | `SampleClock` | 20 MHz from BUS_CLK, initially stopped/API controlled |
| DMA | `SampleDMA` | Hardware request enabled, **rising-edge** request, termination output disabled |
| UART | `HostUART` | Full UART, internal clock, 57600, 8 data, no parity, 1 stop, no flow control, RX/TX buffers 64 |
| Digital Input Pin | `HostRx` | HW connection, digital high-Z |
| Digital Output Pin | `HostTx` | HW connection, strong drive |
| Digital Output Pin | `StatusLED` | **Software controlled** (HW connection unchecked), strong drive, initial value 1 |

### Wires

Make these four schematic connections:

```text
LoopIn digital output  --------------------------> HystOut input
LoopIn interrupt output ------------------------> LoopEdgeISR int_signal
SampleClock clock output ------------------------> SampleDMA drq
HostRx -> HostUART rx        HostUART tx -> HostTx
```

The first wire is important: it makes P12[3] follow P12[2] in programmable
hardware with low delay. R11 then applies positive feedback to the external
phase-detector node. Do **not** replace it with a slow C loop.

The intended schematic is:

```text
                 +---------------- HystOut (P12[3]) -> R11
                 |
LoopIn (P12[2])--+---------------- input signal to fabric
                 |
                 +-> interrupt -> LoopEdgeISR

SampleClock 20 MHz -> SampleDMA request
HostRx -> HostUART 57600 -> HostTx
StatusLED (software controlled)
```

### Component details

#### `LoopIn`

- Pin type: Digital Input.
- HW connection: enabled.
- Drive mode: High Impedance Digital.
- Input buffer: enabled.
- Input synchronization: Transparent/None, not double-synchronized.
- Interrupt: Rising Edge.

The asynchronous input is intentional. Sampling and packet validation provide
the digital filtering; double synchronization would add phase-dependent delay.

#### `HystOut`

- Pin type: Digital Output.
- HW connection: enabled.
- Drive mode: Strong Drive.
- Slew rate: Fast.
- Connect its schematic input directly to `LoopIn`.

#### `SampleDMA`

- Enable hardware request terminal `drq`.
- Hardware request type: Rising Edge.
- Do not enable terminal-out unless Creator requires it for display.
- Burst size and addresses are configured in `capture_dma.c`.

A level-sensitive request can transfer many bytes per clock high period and
corrupt the sample rate. It must request one byte on each 20 MHz rising edge.

#### `HostUART`

- Mode: Full UART.
- Baud: 57600.
- Data: 8 bits.
- Parity: None.
- Stop bits: 1.
- Flow control: None.
- Clock: Internal.
- RX and TX enabled.
- RX/TX software buffer: 64 bytes each.

## 6. Assign the pins

Open `OneLoopDecoder.cydwr`, then the **Pins** tab. Assign exactly:

| Signal | PSoC pin | Physical purpose |
|---|---:|---|
| `LoopIn` | `P12[2]` | Digital output of external phase/input amplifier |
| `HystOut` | `P12[3]` | Feedback through R11 = 4.87 kOhm |
| `HostRx` | `P12[6]` | UART RX / KitProg USB-UART TX |
| `HostTx` | `P12[7]` | UART TX / KitProg USB-UART RX |
| `StatusLED` | `P2[1]` | On-board blue LED, active low |

Do not create normal GPIO assignments for P15[0] and P15[1]. Enabling the MHz
external crystal reserves those pins automatically.

## 7. Configure the 5 MHz clock and 80 MHz CPU

Open `OneLoopDecoder.cydwr`, then **Clocks**. Configure:

1. Enable the MHz external crystal/ECO (`XTAL`).
2. External crystal frequency: **5.000 MHz**.
3. Crystal accuracy: enter the crystal's rated PPM value if known.
4. Crystal load: use the crystal datasheet. With the existing two external 22 pF
   capacitors, approximately 12-13 pF effective load including stray capacitance
   is a reasonable starting value; do not blindly change fitted capacitors.
5. PLL source: external crystal/ECO.
6. PLL output: **80 MHz** (5 MHz x 16).
7. Master clock source: PLL, divider 1 -> **80 MHz**.
8. BUS_CLK: master clock, divider 1 -> **80 MHz**.
9. `SampleClock`: confirm Creator resolves it to **20 MHz**, normally BUS_CLK / 4.

The constants in `timebase.h` require an 80 MHz bus/core clock. A 24 or 64 MHz
build will run but timestamps and the 20 MS/s demodulator assumptions will be
wrong.

The external 5 MHz crystal is connected only across:

```text
P15[0] ---- 5 MHz crystal ---- P15[1]
   |                              |
  22 pF                          22 pF
   |                              |
  GND                            GND
```

It is the precision reference for both sample timing and passage timestamps.

## 8. Generate, build and check

1. Select **Build > Clean OneLoopDecoder**.
2. Select **Build > Generate Application**.
3. Select **Build > Build OneLoopDecoder**.
4. The result must be **0 errors**.
5. In `Generated_Source/PSoC5/project.h`, verify that headers exist for:
   `LoopIn`, `LoopEdgeISR`, `SampleClock`, `SampleDMA`, `HostUART`, and
   `StatusLED`.
6. Check the build report:
   - device is `CY8C5888LTI-LP097`;
   - BUS_CLK is 80 MHz;
   - `SampleClock` is 20 MHz;
   - SRAM use includes the 4096-byte capture buffer and remains below capacity.

Common build errors:

| Error text contains | Cause/fix |
|---|---|
| `SampleDMA_DmaInitialize` | DMA component is missing or not named `SampleDMA` |
| `LoopIn__PS` | pin is missing, renamed, or not a hardware digital input |
| `LoopIn_0_INTR` | Rising-edge interrupt was not enabled in the pin customizer |
| `LoopEdgeISR_StartEx` | Interrupt component missing/renamed |
| `HostUART_...` | UART instance name or RX/TX setting differs |
| `StatusLED_Write` | LED pin missing or not software controlled |

Do not flash if the generated clock report is not correct.

## 9. Program with KitProg

1. Disconnect loop coax and external power for the first programming attempt.
2. Connect the CY8CKIT-059's KitProg PCB USB end to Windows.
3. In Creator select **Debug > Select Debug Target...**.
4. Expand KitProg and select the `CY8C5888LTI-LP097` target.
5. Select **Debug > Program** (not Bootloader Host).
6. Wait for the successful programming message.
7. Press the target reset button once, or unplug and reconnect USB.

This firmware has no bootloader. **Tools > Bootloader Host** and the target
micro-USB connector are not programming methods for this build.

## 10. First serial test without loop hardware

The KitProg USB-UART bridge is already connected to P12[6]/P12[7].

1. Find `KitProg USB-UART (COMxx)` in Device Manager.
2. Open PuTTY, Tera Term, or another serial terminal.
3. Configure **57600 baud, 8 data bits, no parity, 1 stop bit, no flow control**.
4. Reset the PSoC. Expect:

```text
YURLAPS ONELOOP 0.1 READY 57600 8N1; TYPE HELP
```

5. Send these commands, each followed by Enter:

```text
VERSION
SELFTEST
STATUS
MODE DIAG
```

Expected self-test:

```text
SELFTEST PASS id=4961721 vector=F916EFDA353B28290B0BCF3C
```

If this fails, do not connect the loop hardware; first correct the project,
clock or source-file build.

## 11. Connect the decoder input hardware

Power off first.

- **P12[2] does not connect directly to raw coax.** It connects to the output
  node of the existing discrete phase-detector/input-amplifier, after C1/C2 and
  Q2/Q3, biased by R9/R10.
- **P12[3] connects only through R11 = 4.87 kOhm to that same detector node.**
- Decoder ground, loop-amplifier/coax shield and PSoC ground must share the
  intended existing ground arrangement.
- The existing 5 MHz crystal remains across P15[0]/P15[1].
- Verify the board's approximately 4 kOhm VCC-to-GND resistance and expected DC
  test voltages before inserting/powering the PSoC, as in the original decoder
  build procedure.

Place one known transponder close to the loop for the first test. In diagnostic
mode, a successful result resembles:

```text
SCAN samples=4096 preambles=10 rejects=0 valid_candidates=10 unique=1
PKT raw=F916EFDA353B28290B0BCF3C id=4961721 status=0 t_qms=1234 q=100 sample=811 valid=1
4BB5B9000004D2
PASS id=4961721 t_qms=1234 hits=3 q=98 status=510 raw=F916...
```

The on-board blue LED turns on for 100 ms when a valid packet is found.

## 12. Diagnose without an oscilloscope

Use `STATUS` and interpret counters in this order:

1. `SELFTEST PASS` proves the UART and packet codec work.
2. `dma_errors=0` proves DMA resources were allocated.
3. `triggers=0` while a known transponder is near the loop means P12[2] is not
   crossing a digital threshold. Check loop amplifier, coax, detector DC
   voltages, P12[2] assignment and P12[3]/R11 wiring.
4. `triggers` and `windows` increase but `preambles=0`: activity exists, but it
   does not correlate as a 5 MHz/1.25 Mbit/s differential packet. Check the
   5 MHz crystal/80 MHz clock report, amplifier clipping/noise and transponder.
5. `preambles` increases and `rejects` increases: much of the header is visible,
   but coded payload bits are wrong. Reduce noise/clipping, move the transponder
   closer and verify the DMA request is rising-edge, not level-sensitive.
6. `packets` increases: physical decode is working.
7. `passages` increases and 14-character records appear: YurLaps-facing output
   is working.

Record a `STATUS` line for each loop length/distance test. Later firmware should
add a command to export frozen raw sample windows; that will give deeper signal
analysis without an oscilloscope.

## 13. Connect to ESP32-C3/YurLaps safely

The PSoC UART pins can operate at the PSoC I/O supply voltage, commonly 5 V.
ESP32-C3 pins are not 5-V tolerant.

- P12[7] is PSoC TX and goes to ESP RX **through a proper level shifter or a
  verified resistor divider**.
- P12[6] is PSoC RX and receives ESP TX through a level-compatible buffer if
  bidirectional commands are needed.
- Connect grounds.
- Do not connect PSoC TX directly to ESP RX unless measurements/schematic prove
  the signal is already limited to 3.3 V.

Use `MODE CANO` before normal YurLaps operation so only 14-character records are
sent (apart from the one reset banner).

## 14. Recovery and rollback

### Creator cannot acquire the target

1. Close all serial terminals and PSoC Programmer.
2. Unplug external power/coax.
3. Unplug/reconnect KitProg directly to the PC, avoiding an unpowered hub.
4. Open PSoC Programmer and update KitProg firmware if offered.
5. Return to Creator and use **Debug > Select Debug Target** again.
6. If needed, hold target reset while acquisition starts, then release it.

### Firmware runs but serial is dead

1. Confirm you selected KitProg USB-UART, not the target micro-USB device.
2. Confirm 57600 8-N-1 and no flow control.
3. Confirm UART pins are P12[6] RX and P12[7] TX.
4. Rebuild and reprogram; press target reset.

### Restore the original decoder

1. Open **PSoC Programmer**.
2. Select the KitProg target and the exact original published HEX.
3. Program and verify.
4. Power off, restore the photographed wiring, then power on and retest with the
   original terminal/software settings.

Programming through SWD/KitProg remains available even when application clocks,
DMA or UART firmware are broken, so a bad application build normally does not
brick the CY8CKIT-059.
